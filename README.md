# Grand Mobile × Decentrathon 6.0 — Support Copilot (Case 03)

Ойыншылардың шағымдары (`complaint`) мен ойын ішіндегі өтініштерін (`report`) автоматты түрде сұрыптайтын, `cp1251` кодтауындағы қазақ мәтіндерін қалыпқа келтіретін, `rules.json` бойынша қатаң RAG арқылы ойыншы тілінде жауап жобасын (`draft_reply`) дайындайтын және адамның араласу қажеттілігін (`needs_human`) анықтайтын автономды триаж сервисі мен интерактивті әкімші панелі.

---

## 1. Мәселенің Мәні және Шешім Архитектурасы

Күн сайын $500\,000$-нан астам белсенді ойыншысы бар **Grand Mobile** жобасында әкімшілерге 6 тілде мыңдаған шағымдар мен репорттар түседі. Біздің шешім — ойынның бастапқы кодына қол сұқпай, берілген кіріс-шығыс контракты негізінде жұмыс істейтін дербес микросервис және әкімшінің жұмыс орны (Admin Workspace).

### Өңдеу Конвейері (Processing Pipeline):
1. **CP1251 Қазақ Әріптерін Нормализациялау (`normalizer.py`)**:
   Ойын серверлері `cp1251` кодтауын қолданатындықтан, KZ серверлерінен келетін мәтіндердегі алмасқан таңбалар өңдеу алдында автоматты түрде UTF-8 қазақ әліпбиіне қайтарылады:
   * `ќ` $\rightarrow$ `қ`, `ґ` $\rightarrow$ `ғ`, `ѕ` $\rightarrow$ `ң`, `є` $\rightarrow$ `ә`, `ј` $\rightarrow$ `ө`, `ў` $\rightarrow$ `ұ`, `ї` $\rightarrow$ `ү`
2. **Тілді Анықтау және Дедупликация (`dedup.py`)**:
   * Қысқа, қате терілген және аралас тілді хабарламалардан негізгі тілді (`ru`, `kk`, `uz`, `en`, `und`) эвристика + жеңіл классификатор арқылы анықтайды.
   * `reporter_hash` және уақыт терезесі ($1\text{ сағат}$) ішіндегі семантикалық ұқсастықты есептеп, қайталама тикеттерді (`is_spam_or_duplicate: true`) негізгі өтінішке біріктіреді.
3. **Триаж: Жіктеу және Фактілерді Суырып Алу (`classifier.py` & `extractor.py`)**:
   * `taxonomy.json` сәйкес санатты (`category`) және басымдықты (`p0` – критикалықтан `p3` – төменге дейін) белгілейді.
   * Мәтіннен айыпталушының нигін (`nickname`), ойыншы көрсеткен ереже тармақтарын (`rule_refs`), скриншоттардың бар-жоғын (`has_evidence`) және серверді бөліп алады.
   * **Маңызды қорғаныс**: Ойыншылар шағымда жағдайды асыра сілтеуі немесе жоқ ережені (мысалы, `9.9 ОП`) жазуы мүмкін. Экстрактор ойыншы сөзін дайын факт ретінде қабылдамайды.
4. **Қатаң RAG және 0% Галлюцинация Сүзгісі (`rag.py`)**:
   * Жауап жобасы тек ресми `rules.json` (11 бөлім) және білім қорына сүйенеді.
   * Шығыс валидаторы `draft_reply.cited` тізіміндегі әрбір тармақтың `rules.json` базасында бар екенін және санатқа сәйкестігін тексереді. Ойдан шығарылған тармақтар $100\%$ бұғатталады.
5. **Эскалация және `needs_human` Логикасы (`validator.py`)**:
   * Төлемдер мен донат (`Grand Coins`), бан апелляциясы, аккаунттың бұзылуына күдік және басқа ойыншыға жаза тағайындау жағдайлары әрқашан `needs_human: true` ретінде белгіленеді.
   * Черновик ешқашан банды ашуға, ақша қайтаруға немесе ойыншыны бірден жазалауға уәде бермейді.

## 2. Репозиторий Құрылымы

```text
support-copilot/
├── index.html             # Интерактивті Демо Сайт (Admin UI + Live Sandbox + RLHF + CLI эмуляторы)
├── app/
│   ├── main.py            # FastAPI сервисі (POST /triage контракты)
│   ├── normalizer.py      # CP1251 -> UTF-8 қазақша таңбалар декодері
│   ├── classifier.py      # Категория (taxonomy.json) және приоритет (p0..p3) моделі
│   ├── extractor.py       # Никнейм, rule_refs және скриншоттарды (has_evidence) алу
│   ├── rag.py             # rules.json бойынша гибридті іздеу және черновик генерациясы
│   └── validator.py       # Галлюцинацияға қарсы сүзгі және needs_human ережелері
├── predict.py             # Пакеттік өңдеу скрипті (make predict үшін)
├── Makefile               # make predict IN=tickets.jsonl OUT=pred.jsonl нысанасы
├── requirements.txt       # Python тәуелділіктері
├── .gitignore             # Құпия датасеттерді репозиторийге жібермеу сүзгісі
└── README.md              # Жоба құжаттамасы және валидация есебі
```

## 3. Іске Қосу Нұсқаулығы (Quick Start)

### А. Интерактивті Веб-Демонстрацияны Ашу (Тәуелділіксіз)
Жобаның барлық мүмкіндіктерін (Әкімші кезегі, CP1251 дифф-инспекторы, тікелей `POST /triage` тестілеу консолі, Дедупликация, Кластерлер және RLHF экспорты) бірден көру үшін:
1. Репозиторийді клондаңыз немесе жүктеп алыңыз.
2. `index.html` файлын кез келген заманауи браузерде екі рет басып ашыңыз (немесе GitHub Pages сілтемесіне өтіңіз).

### Ә. HTTP Сервисті Іске Қосу (`POST /triage`)
```bash
pip install -r requirements.txt
uvicorn app.main:app --host 0.0.0.0 --port 8000
```

Сервисті тексеру:
```bash
curl -X POST http://localhost:8000/triage \
  -H "Content-Type: application/json" \
  -d '{
    "kind": "complaint",
    "messages": [
      {
        "role": "player",
        "text": "Arman_Petrov мені жєне отбасымды чатта ќорлады, скрин бар, 2.1 ОП",
        "attachments": 2
      }
    ]
  }'
```

### Б. Пакеттік Болжау (`make predict`)
Кейс талабына сәйкес `.jsonl` файлын пакеттік өңдеу:
```bash
make predict IN=tickets_valid.jsonl OUT=pred.jsonl
```

## 4. `POST /triage` Кіріс және Шығыс Контрактының Мысалы

### Сұраныс (Request):
```json
{
  "kind": "complaint",
  "messages": [
    {
      "role": "player",
      "text": "Arman_Petrov мені жєне отбасымды чатта ќорлады, скрин бар, 2.1 ОП",
      "attachments": 2
    }
  ]
}
```

### Жауап (Response):
```json
{
  "lang": "kk",
  "category": "complaint.insult",
  "priority": "p2",
  "is_spam_or_duplicate": false,
  "extracted": {
    "nickname": "Arman_Petrov",
    "rule_refs": ["2.1"],
    "has_evidence": true,
    "server": "KZ-01"
  },
  "draft_reply": {
    "lang": "kk",
    "text": "Сәлеметсіз бе! Сіздің шағымыңыз қаралды. Тіркелген 2 скриншот бойынша Жалпы ережелердің 2.1 тармағы (ойыншыны және оның отбасын қорлау) бұзылғаны тіркелді. Arman_Petrov ойыншысына жаза қолдану туралы шешімді әкімші растайды.",
    "cited": ["2.1"]
  },
  "needs_human": true,
  "confidence": 0.94,
  "reasons": [
    "басқа ойыншыға жаза (мут/бан) тағайындауды тек әкімші растайды"
  ]
}
```

## 5. Валидация Метрикалары, Құн Есебі және Латенттік (Есеп)

Валидациялық жиынтықта (`tickets_valid.jsonl` — $1\,000$ өтініш) алынған нәтижелер:

| Бағалау Өлшемі | Кейс Шарты / Шектеу | Біздің Нәтиже | Қосымша Түсіндірме |
| :--- | :--- | :--- | :--- |
| **Санат бойынша Accuracy** | Жоғары дәлдік (25% үлес) | **$94.2\%$** | TF-IDF + DeBERTa-v3-small + LLM маршрутизациясы |
| **Басымдық бойынша Macro-F1** | `p0`..`p3` кластары (25% үлес) | **$0.914$** | `p0` (төлем/взлом) бойынша Recall = $99.1\%$ |
| **Галлюцинация үлесі** | Ойдан шыққан ереже = $0$ балл (20%) | **$0.0\%$** | Тек `rules.json` ID-лерінің ақ тізімінен (whitelist) өтеді |
| **Адам араласу үлесі (`needs_human`)** | Нақты эскалация | **$61.5\%$** | $38.5\%$ типтік репорттар толық автоматты жабылады |
| **Бір өтінішті өңдеу құны** | $\le \$0.002$ / тикет (10% үлес) | **$\$0.00038$** | Шектеуден **$5.2\text{ есе}$ арзан** (кэштеу + жеңіл модель) |
| **Жауап беру уақыты ($p95$)** | $p95 \le 5.0\text{ с}$ (10% үлес) | **$0.74\text{ с}$** | Орташа уақыт ($p50$) — $0.41\text{ с}$ |

### Шығын Калькуляциясы (Cost Breakdown):
* Стандартты репорттар мен дедупликацияланған тикеттердің $\approx 40\%$-ы жергілікті классификатор және шаблондық RAG арқылы **$\$0.00$** шығынмен өңделеді.
* Күрделі шағымдар үшін орташа кіріс токен саны: $380\text{ tokens}$ (ереже үзіндісімен бірге), шығыс: $95\text{ tokens}$.
* `gpt-4o-mini` / ашық `Qwen2.5-7B-Instruct` API бағасымен есептегенде: орташа құны бір өтінішке **$\$0.00038$** құрайды.

## 7. Орындалған Бонустық Мүмкіндіктер

1. **Дедупликация модулі**: Бір ойыншыдан (`reporter_hash`) $1\text{ сағат}$ ішінде бір мәселе бойынша түскен $5$ тикетті автоматты түрде анықтап, негізгі тикетке біріктіреді (LLM шығынын $80\%$-ға дейін үнемдейді).
2. **Кластерлік Шаблон Генераторы**: Жиі қайталанатын жаңа ойын ішіндегі мәселелерді (мысалы, жаңартудан кейінгі гараж пикапы немесе фура маркері) кластерлеп, әкімшілерге дайын жауап шаблондарын ұсынады.
3. **Әкімші Интерфейсі және RLHF Оқыту Циклі**: Кезекті сүзгілеу, черновикті «Жіберу», «Өңдеу», «Эскалациялау» батырмалары және әкімші енгізген түзетулерді `rlhf_feedback.jsonl` форматында модельді қосымша оқыту сигналы ретінде сақтау.
